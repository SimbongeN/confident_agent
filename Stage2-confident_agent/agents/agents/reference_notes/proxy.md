# Proxy
keywords: proxy, proxy pattern, surrogate, placeholder, virtual proxy, remote proxy, protection proxy
- Intent: provide a surrogate or placeholder for another object to control access to it. Also known as Surrogate. Object structural.
- Use whenever a more versatile or sophisticated reference than a simple pointer is needed. Kinds listed: remote proxy (local representative for an object in another address space; a.k.a. "Ambassador"), virtual proxy (creates expensive objects on demand), protection proxy (controls access by rights), smart reference (extra actions on access, e.g. reference counting, lazy loading of persistent objects, lock checks).
- Participants: Proxy (holds a reference to the real subject, provides an interface identical to Subject, controls access and may create/delete the real subject), Subject (common interface so a Proxy can be used anywhere a RealSubject is expected), RealSubject (the real object represented).
- Collaboration: the proxy forwards requests to the RealSubject when appropriate, depending on the kind of proxy.
- Consequence: adds a level of indirection that can hide that an object is remote, create objects on demand, or perform housekeeping. Copy-on-write is another optimization a proxy can hide: copying is postponed until the subject is modified (requires reference counting).
- Known uses: ET++ image proxy (motivating example: Graphic/ImageProxy/Image, with the proxy caching the image's extent); NEXTSTEP NXProxy; Choices KernelProxies; Orbix creates proxies via Factory Method.
- Distinguishing (book): Adapter provides a different interface to the adapted object, whereas a proxy provides the same interface (though a protection proxy may refuse operations, so its interface is effectively a subset). Decorator may be implemented like a proxy but adds responsibilities, whereas a proxy controls access.
- Further (Structural discussion): Proxy is not concerned with attaching/detaching properties dynamically and is not designed for recursive composition; the subject defines the key functionality and the proxy provides or refuses access, whereas in Decorator the component provides only part of the functionality and decorators furnish the rest.
