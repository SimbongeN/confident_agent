# DRY, KISS and YAGNI
keywords: DRY, don't repeat yourself, KISS, keep it simple stupid, YAGNI, you aren't gonna need it, WET, design principles, extreme programming
- DRY (Don't Repeat Yourself) reduces repeated information likely to change, replacing it with abstractions or data normalization.
- DRY states: "Every piece of knowledge must have a single, unambiguous, authoritative representation within a system."
- Andy Hunt and Dave Thomas formulated DRY in The Pragmatic Programmer (1999) and applied it to schemas, test plans, build systems and documentation too.
- WET, commonly "write everything twice", is the opposing view.
- KISS ("Keep it simple, stupid") is a design principle holding that simplicity should be a core design goal.
- KISS is credited to the US Navy (1960) and associated with Lockheed engineer Kelly Johnson; "stupid" reflects equipment being repairable by an average mechanic with basic tools.
- YAGNI ("You aren't gonna need it") is an extreme programming (XP) principle: do not add functionality until it is actually needed.
- Ron Jeffries: "Always implement things when you actually need them, never when you just foresee that you [will] need them."
- YAGNI underlies XP's "do the simplest thing that could work" and is meant to be combined with continuous refactoring, automated unit testing and continuous integration.
- Without continuous refactoring, YAGNI can lead to disorganized code and costly rework (technical debt).
