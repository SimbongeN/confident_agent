# Software requirements and specification documents
keywords: SRS, software requirements specification, system requirements specification, SysRS, software design specification, SDD, design document, test specification, integration specification, IEEE 830, IEEE 1016, IEEE 829
- An SRS (software requirements specification) describes a software system to be developed, laying out functional and non-functional requirements and possibly use cases.
- An SRS forms the basis of an agreement between customers and suppliers about how the product should function.
- An SRS is a rigorous review of requirements before detailed system design, and provides a basis for estimating cost, risk and schedule.
- Requirements should describe what is needed, independent of design, not how the software accomplishes it.
- ISO/IEC/IEEE 29148 superseded IEEE 830 and covers broader scope including business and stakeholder requirements specifications.
- A System Requirements Specification (SysRS) is "a structured collection of information that embodies the requirements of a system" and is a separate document from the SRS.
- A software design description (SDD, also software design document) records a software design, addresses design concerns and communicates them to stakeholders.
- An SDD typically covers data design, architecture design, interface design and procedural design; IEEE 1016-2009 defines its content using design viewpoints.
- A test plan is a document detailing the objectives, resources and processes for a test session, covering test coverage, test methods and test responsibilities.
- IEEE 829 documents include a Level Test Design (test cases, expected results, pass criteria), Level Test Case (test data) and Level Test Procedure (how to run each test).
- Integration tests defined in an integration test plan are applied to unit-tested modules grouped into larger aggregates; the output feeds system testing.
